Codex 额度怎么算，用完了先看哪一道窗口

写代码写到一半，Codex 提示额度用完，第一反应常常是这档会员买错了。更常见的情况其实是：有一道窗口刚刚用满，另一道可能还有剩；或者登录方式不对，根本没用上会员额度。

本文整理时引用自 chong-zhen 的《Codex Plus和Pro区别》。Codex 在 Plus、Pro 10x、Pro 20x 上的限制有何不同，剩余量和重置时间要去哪里看，都以 Codex Plus和Pro区别 这一页为准。chong-zhen 是独立的第三方充值服务，由 Hong Kong Prompt Limited 运营，与 OpenAI 无隶属关系，没有美金卡的用户也可以在这里给自己的账号开会员。价格一律以网站为准。

Codex 并没有单独可充的额度

Codex 是用来辅助写代码的工具，桌面应用、命令行、编辑器插件和网页版都可以用，但不能单独为它再充一笔额度。它用的就是你 ChatGPT 账号上的会员额度：账号开的是 Plus，Codex 就按 Plus 的额度算；开的是 Pro，就按对应 Pro 档位算。同一份额度在这些用法里是共用的，不必分开再充一次。

要用上这份会员额度，登录时必须选「用 ChatGPT 账号登录」。如果改用 API Key 登录，走的是另一套按量计费，和会员额度不是一回事，也不能靠它来使用已经开通的 Plus 或 Pro 额度。装好之后，可在 ChatGPT 网页的「设置 → 用量」里查看剩余量和重置时间；用命令行的，也可以输入 /status 查看。还要记住，这份额度并不是 Codex 专用的。同一个账号在聊天里用模型、做研究，和在 Codex 里写代码，用的是同一份会员额度。聊天用得多，Codex 能用的就会变少，反过来也一样。Codex 一次任务往往更耗额度，所以主要写代码的人，会比只聊天的人更早碰到上限。

用量按两道窗口算，各档限制并不一样

按目前帮助中心的说法，Codex 的用量按两个窗口计算：一个约 5 小时的窗口，一个每周窗口。5 小时窗口用满了，每周额度往往还有剩，等短窗口恢复就能接着用；每周窗口用满了，就要等到每周重置。具体剩多少、几点重置，每个账号不一样，以用量页上当时显示的为准。

各档的差别，主要就在这两道限制怎么生效：

  • Plus 同时受 5 小时和每周两道限制。短窗口先碰到上限，并不等于这一周已经没有额度。
  • Pro 10x（原 5x）、Pro 20x，以及更高的档位，按目前的说明没有 5 小时限制，主要看每周额度。页面也写明规则会调整，不要把某一次看到的数字当成长期标准。
  • 档位名称里的 10x、20x，是沿用以前的叫法。页面写明目前并不公布具体倍数，也不能把名称直接换算成固定的消息条数，实际上限以账号用量页为准。

同样是 Plus，不同任务消耗也会差很多。上下文长短、思考档位、工具调用，以及云端任务，都会让同一模型用得更快或更慢。这些只说明用量快慢会波动，不能事先折成一个确定的次数。

额度用完了，按这个顺序处理

先不要急着换套餐。打开用量页，看清楚是哪一道窗口满了、几点重置，再决定下一步。

  1. 等对应窗口重置。5 小时窗口满了，等窗口恢复；每周额度满了，等到用量页给出的重置时间。这是不另外付费的办法，适合并不急着立刻继续的时候。
  2. 先换一个还有余量的模型。某个模型的额度用完了，其他模型可能还有剩。要紧、但不一定非要用当前模型的任务，可以先换过去；更复杂的任务，不妨留到窗口恢复后再做。
  3. 部分个人 Plus、Pro 账号可以购买即时重置，两个窗口会立刻恢复，但不能存着以后用。能不能买，要看账号和账单地区，以账号里当时显示的为准。
  4. 如果只是偶尔碰到上限，等一等或换个模型通常就够。如果一周里多次用完，才说明当前这一档已经不够用，再考虑升到更高档。

需要记住：额度是对方按账号计算的，充值平台不能代为重置。额度用完只是暂时没法继续用同一档的这部分能力，窗口恢复后可以照常使用，也不会因此把会员降到更低档。

经常不够用、想换更高档时

升级是经常用完之后才要考虑的事，不是一提示上限就立刻该做的事。对照页面上的说明：偶尔改代码、写脚本，Plus 通常够用；每天都写代码并且经常被提示额度用完，再看 Pro 10x；需要长时间、多任务并行时，再看 Pro 20x。这只是站点自己的判断，并不是硬性标准。先连续看一段时间自己的用量页，记下每周额度大概在周几用完、5 小时限制碰到过几次，会比凭感觉更准。

如果已经决定换更高档，还要注意：有效会员不能叠加。本站充值要求账号是免费状态，Plus 尚未到期时，不能直接在这里再开一档 Pro，需要等到期、账号回到免费版后再下单。着急的话，先联系页面客服，按账号当时的情况处理。

平时也可以少碰到上限：一个对话里聊得太长会更耗额度，换话题时开新对话；尽量把需求一次说清楚，减少来回返工；简单问题先用更轻量的模型，复杂任务再用更强的模型；让 Codex 动手前先说明要改哪几个文件，避免它把整个项目从头读一遍。

先分清是哪一道窗口满了，再决定是等待、换模型，还是以后再升档。把「设置 → 用量」看成日常要看的一页，比反复猜测自己还能用多久更可靠。
